# k6 のスクリプトの書き方

`loadtest/` の k6 のスクリプトに適用する。k6 は `grafana/k6` のコンテナ (版は `loadtest/Dockerfile` の `FROM` の行。`loadtest/justfile` の `k6_image` が読む) で動かす。

## 書くのはエージェント

> [!IMPORTANT]
> **`loadtest/` の k6 のスクリプトを書く・直すときは、メインのセッションで直接書かず、`k6-author` エージェント (`.claude/agents/k6-author.md`) に任せる。**

- メインのセッションは、頼む内容 (目的、変える範囲、確かめ方) を整理してエージェントに渡し、返ってきた差分と確認の結果を見て、ユーザーに伝える
- 例外: 1 行の値の修正 (RPS の既定値など) は、メインのセッションで直してよい

## 検査

- `just loadtest::inspect` で、組み立てた設定 (シナリオと閾値) を確かめる。リクエストは送らない
- 手元のコンテナ (`just backend::run`) に `just loadtest::run ... http://host.docker.internal:8080` で流し、サマリーと終了コードを確かめる
- `prd` (`https://ecs-lab.tamaco-blog.jp`) に流すのは、ユーザーが検証のときに行う

## ファイルの分け方

- **入り口** (`loadtest/scripts/<名前>.js`): `options` (シナリオと閾値)、`setup()`、シナリオが呼ぶ関数 (`default` か `exec` で指す関数) だけを書く
  - 負荷の形 (executor、RPS、時間) は入り口に置く。共有のモジュールで `options` を組み立てない
  - 1 つの検証 (負荷の形) に 1 つの入り口を作る。処理 (リクエストと判定) は `lib/` を共有する
- **共有のモジュール** (`loadtest/scripts/lib/`): 1 つのファイルに 1 つの役割だけを置く
  - 例: 環境変数の読み込み、失敗の分け方、本文の読み取り、メトリクスの定義、1 種類のリクエストの送り方
- import は、`./lib/config.js` のように拡張子まで書く (k6 は Node.js 式のパスの解決に対応していない)
- 今使わないものは、先回りして作らない

## 値の渡し方

- スクリプトに渡す値は、k6 の `-e` (`k6 run -e RATE=20 ...`) で渡す。`run` と `inspect` で渡し方をそろえる
  - `docker run -e` (コンテナの環境変数) は使わない。`k6 inspect` は既定でコンテナの環境変数を読まず、既定値で組み立ててしまう
- `__ENV` は、環境変数を読むモジュール 1 か所だけで読み、既定値もそこに置く

### 参考 (値の渡し方)

- DOC: <https://grafana.com/docs/k6/latest/using-k6/environment-variables/>

## メトリクスと閾値

- 自作のメトリクス (`Counter` など) は、モジュールの一番上 (init) で作る
- 種類ごとの件数は、`Counter` にタグ (`kind`、`version` など) を付けて数える
- `check` は、判定を名前付きでサマリーに並べるために足す。種類ごとの件数の代わりにはしない
- `check` の結果は、`const ok = check(...)` で受けてから `if (!ok)` で分ける。`if (!check(...))` とまとめない
- 「1 件でも失敗すれば失敗」は閾値で表し、k6 を 99 で終わらせる
  - 失敗した繰り返しは `return` で抜ける。`fail()`、`exec.test.abort()` (108)、`exec.test.fail()` (110) は、終了コードが 99 と違うため使わない
  - 例外: `setup()` で試験に要る前提 (例: 古い版の番号) を読めないときだけ、`exec.test.abort()` で止める (108)。「試験を始められなかった」ことを、「流した結果、失敗が出た (99)」と分けるため
  - `abortOnFail` は付けない。デプロイの最後 (新旧が切り替わり終わるまで) を見るため
- タグには、値の種類が少ないものだけを使う。`cart_id` などの ID や `remote_ip` はタグにしない
- 閾値は、同じキーを 2 回書かない (後ろが黙って無視される)

## HTTP

- JSON の本文は、`JSON.stringify()` した文字列と `Content-Type: application/json` の両方で送る (オブジェクトのまま渡すとフォームの形で送られる)
- パスに ID が入る URL は、`tags: { name: "..." }` か `http.url` で 1 つの名前にまとめる
- 想定どおりのステータスを変えるときは、`http.expectedStatuses(...)` を init で 1 回だけ作り、そのリクエストの `responseCallback` に渡す。default の関数の中で `http.setResponseCallback` を呼ばない
- `Response.json()` は try/catch で受ける。引数なしの `json()` は、本文が JSON でないと例外を出す (引数を付けた `json("version")` は `undefined` を返す。手元で確かめた)

### 参考 (HTTP)

- DOC: <https://grafana.com/docs/k6/latest/using-k6/http-requests/>
- DOC: <https://grafana.com/docs/k6/latest/javascript-api/k6-http/expected-statuses/>

## シナリオ

- 一定の RPS で送るときは `constant-arrival-rate` を使い、`sleep()` は入れない
- `preAllocatedVUs` は「1 回の繰り返しの時間 × RPS + ゆとり」を目安にし、`maxVUs` は小さなゆとりにとどめる。足りない分は `dropped_iterations` の閾値で失敗にする
- 送り手が違うもの (例: 新旧のクライアント) は、シナリオを分け、`exec` で別の関数を呼ぶ。シナリオ名は `scenario` タグとして自動で付く

### 参考 (シナリオ)

- DOC: <https://grafana.com/docs/k6/latest/using-k6/scenarios/>
- DOC: <https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/arrival-rate-vu-allocation/>

## 使わないもの

| 使わないもの                               | 理由                                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| `group`                                    | 1 回の繰り返しで 1 リクエストのため。「1 リクエストに 1 つの group」は推奨されない     |
| `http.batch`、`http.asyncRequest`、`sleep` | 一定の RPS は executor が作る。1 回の繰り返しの長さと送る数の関係が崩れる              |
| jslib (`https://jslib.k6.io/...`)          | 実行のたびにネットワークから読み込む。組み込みで足りる (UUID は `crypto.randomUUID()`) |
| `k6/experimental/*`                        | 破壊的変更が入りうる                                                                   |
| `exec.vu.tags`                             | 非推奨。VU のタグは `exec.vu.metrics.tags` を使う                                      |
| `--summary-export`                         | 推奨されていない。結果をファイルに残すときは `handleSummary` を使う                    |
