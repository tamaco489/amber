# デプロイ中の負荷試験 (k6)

[English](./k6.md) | [日本語](./k6.ja.md)

[ドキュメント一覧](../README.ja.md)に戻る。

リクエストを流している間にデプロイしても、失敗するリクエストが 0 件 (ダウンタイムなし) であることを、k6 で確かめます。
k6 は手元の PC から実行します。負荷試験のための AWS のリソースは作りません。

## 仕組み

- スクリプトは `loadtest/scripts/deploy.js` です。`/` に一定の RPS (`constant-arrival-rate`) で GET を送り続けます
- k6 は手元に入れず、版を固定したコンテナ (`grafana/k6:2.4.0`) で動かします。`loadtest/justfile` の `k6_image` で固定しています
- **1 件でも失敗すると、k6 は 99 で終わります** (閾値の超過)。予定の RPS を送れなかった分 (`dropped_iterations`) も失敗として扱います

### 失敗の種類

| 種類      | 条件                                          | 原因の見当                                        |
| --------- | --------------------------------------------- | ------------------------------------------------- |
| `timeout` | 応答が来ない (既定 10 秒)、接続のタイムアウト | 回線側、または ALB の先で詰まっている             |
| `network` | DNS・TCP・TLS の失敗、接続の切断              | 回線側 (切り替えのときに接続が切られた場合も含む) |
| `server`  | HTTP 5xx                                      | ALB かアプリ側。ALB の 5xx の件数と突き合わせる   |
| `client`  | 200 以外のそのほかの応答 (4xx など)           | 送り先や経路の設定                                |
| `body`    | 200 だが、本文からバージョン番号を読めない    | アプリ側                                          |

ALB の 5xx が 0 件なのに `timeout` や `network` が出たときは、手元の回線の問題と判断します。
失敗した 1 件ごとに、種類と `status`・`error_code` をログ (`level=warning`) に出します。

### バージョンごとの件数

本文の `{"version":"v1"}` を読み、`responses{version:<番号>}` に数えます。数える番号は `versions` で渡し、それ以外の番号は `unknown` に数えます。
ローリングでは途中から新旧が混ざり、カナリアやリニアでは段階ごとに割合が変わります。

## 実行する

送り先が動いている間だけ実行します。`prd` は `enable_runtime = true` の間だけ動きます ([検証環境の停止と再開](../infra/runtime.ja.md))。
回線の瞬断や PC のスリープでも失敗になるため、有線でつなぎ、実行中はスリープしないようにします。

```sh
# 引数は rate (1 秒あたりの件数)、duration、versions、base_url の順。省略すると 10 RPS で 5 分
just loadtest::run 20 10m v1,v2

# 流している間に、別の端末から v2 のタグを push してデプロイする
```

デプロイが終わるまでの時間より長い `duration` を渡します。

### 終わったときの出力

サマリーの `THRESHOLDS` と `CUSTOM` に、失敗の種類ごとの件数と、バージョンごとの件数が出ます。

```text
    CUSTOM
    failures.......................: 0     0/s
      { kind:body }................: 0     0/s
      { kind:client }..............: 0     0/s
      { kind:network }.............: 0     0/s
      { kind:server }..............: 0     0/s
      { kind:timeout }.............: 0     0/s
    responses......................: 300   19.998305/s
      { version:unknown }..........: 0     0/s
      { version:v1 }...............: 300   19.998305/s
      { version:v2 }...............: 0     0/s
```

## 手元のコンテナで試す

AWS を動かさずに、スクリプトの動きを確かめられます。

```sh
just backend::build v1
just backend::run v1   # 別の端末で動かしておく

# コンテナの中の k6 から、手元の 8080 番に送る
just loadtest::run 20 15s v1,v2 http://host.docker.internal:8080
```

途中でコンテナを止めると、`network` の失敗が数えられ、99 で終わることを確かめられます。

スクリプトを書き換えたときは、`just loadtest::inspect` で、組み立てた設定 (シナリオと閾値) を確かめられます。リクエストは送りません。
